- [x] Phase 6: SLA engine — done. app/sla/sla_engine.py models Resolution Time as a running/paused timer: `start_for_issue` creates an `sla_instances` row per org SLA (called from `issue_service.create_issue`, so API- and channel-created issues both get one; audit `sla.started`); counting statuses are New/On You/On Customer, On Hold/Closed pause it. Because the schema has no paused_at column, `on_status_change` (called from `issue_service.add_message` and the trigger `set_status` action) folds a finished pause into `paused_seconds` when the issue returns to a counting status, and the *open* pause start is derived from audit_logs (latest counting->non-counting `issue.status_changed` row, so On Hold->Closed counts as one pause). `elapsed_seconds` = now - started_at - paused_seconds - open pause. `check_breaches` sets `breached_at` once an instance's counting time reaches `target_minutes` and writes `sla.breached:<name>` to audit_logs (target = the issue; the dashboard in Phase 7 surfaces this); `run_breach_checker` runs it every 30s as an asyncio background task started in main.py's lifespan next to the event-bus worker. seed.py now also seeds a "Resolution Time" SLA (480 min), idempotently. `counts_business_hours_only` is stored but not enforced (v1 treats all SLAs as 24/7; PLAN.md doesn't define business hours). Verified with a scratch script on a temp DB: instance created on issue creation; elapsed ≈ 100 min while counting; a 60-min On Hold pause is excluded (open and after resume, `paused_seconds` ≈ 60 min); On Hold->Closed stays the same pause; no breach at 40/480 min; breach fires once at 600 min with an `sla.breached` audit row and is not re-fired.
- [x] Phase 7: Real-time dashboard — done. app/realtime/ws_manager.py: a `ConnectionManager` plus a `/ws` WebSocket route; on connect a client gets a full JSON snapshot (all issues with tags, SLA state, messages, plus the latest 100 audit_logs), and a SQLAlchemy `after_commit` listener on `Session` calls `notify_changed()` so *any* DB write (event-bus worker, REST API, trigger actions, SLA breach checker) rebroadcasts a fresh snapshot to every connected client — debounced 150 ms so a message's several commits coalesce into one push.
